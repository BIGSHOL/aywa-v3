# 침산 DB 기반 원장·경영자 웹앱 시안

기존 대시보드를 참고하지 않고 DB의 업무 관계와 기록을 바탕으로 만든 독립 dev 시안입니다. 일반 배포는 하지 않았습니다. 구성은 셋입니다.

- **AX 업무 흐름(중심)** — 일이 생기면 규칙이 담당자를 정하고, 역할별 수신함에서 처리·보고하면 다음 사람의 일로 이어집니다. 원장은 흐름을, 관리자는 배정·지연·검토를, 직원은 내 할 일을 봅니다. 설계와 검증은 [FLOW-ENGINE.md](FLOW-ENGINE.md)에 있습니다.
- **작업 공간 41개** — 2.0 메뉴 이름 그대로의 상세·근거 화면입니다. 흐름에서 파고들어 갑니다(`workspace-catalog.js`).
- **기록 화면 13개** — 학생·수업·수납·직원·소통·차량·결재·교재·문서·일정의 추이와 상세 맥락입니다.

## 실행

복사본 DB는 이미 준비돼 있습니다. Docker Desktop(컨테이너 `aywa-full-db`)이 켜진 상태에서 저장소 루트에서 실행합니다.

```powershell
node experiments/owner-concept/serve.mjs
```

주소는 **http://127.0.0.1:4310** 입니다. 서버는 로컬 주소에만 바인딩하며 이미 복사한 Docker DB만 읽습니다. 원본 접속 정보가 없어도 실행됩니다. DB 검증 결과와 활성 백업의 시점이 일치하지 않으면 시작하지 않습니다. 집계는 서버 시작 시 읽으므로 복사본을 변경하면 서버를 다시 실행합니다. 복사본을 처음부터 다시 만들 때만 아래 '전체 복사본' 절의 도구를 씁니다.

AI 판정은 선택입니다. 숫자 판정은 Jev(`jev-1.14.0` 고정), 설명 초안은 이 PC의 Claude 구독 CLI(`claude -p`)로 돌며 Anthropic API 키는 쓰지 않습니다. Jev를 쓰려면 `OWNER_CONCEPT_TYPESAFE_KEY_FILE`에 `TYPESAFE_API_KEY=` 한 줄이 든 로컬 파일의 절대 경로를 지정합니다(키 값을 저장소에 두지 않습니다). 키가 없으면 판정 없이 일을 그대로 두고 이유를 표시합니다. 자세한 내용은 [AI-DECISIONS.md](AI-DECISIONS.md)에 있습니다.

## 전체 복사본과 저장 위치

2026-10-27 14:34 KST 기준 원본 DB 전체를 읽기 전용 트랜잭션에서 복사했습니다. 일부 업무 테이블을 선택했던 초기 방식은 폐기했습니다.

| 항목 | 결과 |
|---|---|
| DB 범위 | 19개 스키마, 337개 테이블, 623,499행 |
| 데이터 검증 | 같은 원본 스냅샷과 모든 테이블의 행 수·내용 지문 일치 |
| 구조 검증 | 스키마별 함수·트리거·정책·제약조건 수 일치 |
| Storage 파일 | 8,286개, 13,734,108,640바이트, 실패 0개 |
| Docker 디스크 | `F:\aywa-dev\docker-engine\DockerDesktopWSL` |
| 백업·첨부파일·검증 결과 | `F:\aywa-dev\full-db` |
| 로컬 DB | `aywa-full-db` / `aywa_full_snapshot` / `127.0.0.1:5444` |

DB의 모든 지점 데이터와 관계를 보존했고 화면에서는 `cs` / 인재원 침산을 선택합니다. 인증·내부 스키마와 기존 보관 자료도 복사본에 포함됩니다. 화면으로 전달하는 정보는 필요한 업무 필드로 제한합니다. `snapshot-tables.mjs`는 화면 집계의 입력 목록이며 백업 범위를 제한하지 않습니다.

활성 백업은 F 드라이브의 `current-backup.json`이 가리킵니다. 성공한 백업만 이 포인터를 갱신합니다. `verification.json`은 테이블별 대조 결과, `storage/manifest.json`은 파일 경로·크기·SHA-256·원본 체크섬 대조 결과를 담습니다. 외부 Google Drive 등 제3자 서비스의 링크는 DB에 보존되지만 해당 서비스의 파일 본문까지 내려받았다는 뜻은 아닙니다.

로컬 PostgreSQL은 원본과 같은 17.6입니다. `pg_net` 런타임은 원본 0.20.3, 로컬 0.20.4로 차이가 있습니다. DB의 외부 네트워크는 차단했고 해당 워커는 빈 유지관리 DB에 한정했습니다. 원본 서비스나 발송 작업을 로컬에서 재실행하지 않습니다. 로컬 접속 비밀번호는 별도로 생성합니다.

저장 위치 포인터는 Git에서 제외되는 `work/owner-concept/storage-location.json`입니다.

```json
{"root":"F:/aywa-dev/full-db"}
```

처음부터 새 복사본을 만드는 도구는 `backup-full-db.mjs` → `setup-full-db.mjs` → `restore-full-db.mjs` → `verify-full-db.mjs` → `copy-storage.mjs` 순서입니다. 현재는 이미 완료됐으므로 다시 복사할 필요가 없습니다. 복원 도구는 기존 DB를 덮어쓰지 않습니다. 원본을 읽는 두 복사 도구만 `SOURCE_ENV_FILE`을 사용하며 기본값은 `D:/eywa_refactoring/.env.local`입니다. 나머지는 로컬 DB만 사용합니다.

## 화면의 데이터 기준

- 현재 재원은 테스트 학생을 제외한 학생 상태 기준 334명입니다. 월별 청구 대상 학생 수는 현재 재원과 구분합니다.
- 청구액은 **할인 전 금액 − 할인액**, 잔액은 **청구액 − 수납액**으로 계산합니다. 취소·환불 청구는 제외합니다. 10월 실제 청구액 130,266,625원, 누적 수납 129,937,625원, 남은 금액 329,000원·14건을 대조했습니다.
- 과거 청구월의 수납액도 복사 시점까지 받은 누적 금액입니다. 입금 발생일 기준 현금 흐름이나 확정 손익으로 표현하지 않습니다.
- 2020년부터의 이전 장부 재원 기록은 별도의 장기 흐름으로 제공합니다. 현재 학생 상태·청구 대상과 기준이 다르므로 같은 시계열로 합치지 않습니다.
- 시험별 대상·만점이 다른 점수는 시험별로 구분합니다. 기록이 없는 기간을 가상 추이로 채우지 않습니다.
- 직원 화면은 실제 급여명세서 7건을 포함합니다. 명세서 발급·지급 예정과 실제 송금은 구분합니다.
- 차량의 탑승 기록 부재를 미탑승이나 결석으로 단정하지 않습니다.

## 저장되는 것과 저장되지 않는 것

- **흐름 처리(로컬 저장)** — 흐름 화면의 요청 만들기·확인·보고·검토·재배정·시나리오는 DB가 아니라 별도 파일 저장소 `F:/aywa-dev/owner-flow/<작업트리>/<지점>-<복사 시각>/state.json`에 남고 재시작해도 유지됩니다. 이 기록은 `origin: 'dev'`로 복사본 기록(`origin: 'snapshot'`)과 구분되며 학원 실적 지표에 섞지 않습니다.
- **기록 화면의 흉내 동작(페이지 메모리)** — 기록 화면 13개의 상담 단계 이동·답글·메모·일정·설정 변경은 현재 페이지 메모리에서만 동작하며 새로고침하면 초기화됩니다.
- **작업 공간의 동작** — 미리보기와 요청 초안입니다. 2.0 기록을 바꾸지 않습니다.
- 원본·복사본 DB 쓰기, 실제 발송(슬랙·알림톡·ClassNote)·결제는 어디에도 연결하지 않았습니다. 로컬 첨부파일 내려받기와 월별 지표 CSV 저장은 동작합니다.

## 2.0 대비 범위

[catalog/AUDIT.md](catalog/AUDIT.md)가 2.0 전체를 원문으로 회계합니다. 페이지 186·API 92·서버 액션 파일 252(export 730)·47개 패밀리입니다. export마다 묶음·권한·쓰는 표·외부 연동·3.0 목적지를 [catalog/operation-coverage.json](catalog/operation-coverage.json)에 기록했습니다. 2.0의 쓰기 export 588개(본문 추적 · 1차 파일 단위 추정 511개) 가운데 이 시안에서 2.0 기록까지 가는 것은 **0개**입니다. 3.0은 목적지·미리보기·요청 흐름까지만 갖췄으며 운영 기능과 같지 않습니다.

스크롤바는 숨기고 휠·트랙패드·터치·키보드의 기본 스크롤을 유지합니다. 내용이 더 있는 가장자리에만 페이드가 표시됩니다. 메뉴를 이동해도 왼쪽 메뉴의 스크롤 위치를 유지합니다.
